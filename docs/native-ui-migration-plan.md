# 原生 UI 迁移计划

状态：2026-09-27 用户授权开始，已进入独立原生原型阶段；正式界面尚未替换。进展见 [原型首轮记录](native-ui-prototype-results.md)。

**先读：[完整执行与验收清单](native-ui-execution-checklist.md)**；第一阶段详见 [原型任务计划](native-ui-phase1.md)。

## 1. 当前版本与回退点

- 仓库：https://github.com/alent17/Wind0ws_Dynamic_island
- 准备分支：`codex/native-ui-preparation`
- 迁移前源码基线：`e1e050a`（顶部纯图标工具栏、页面释放、辅助窗口按需创建、媒体与频谱修复）。
- 基线已推送。后续原生实现使用 `codex/native-ui-prototype` 分支，从包含本计划的准备分支创建；产品代码基线为上述提交，旧版继续可构建。
- 本次上传源码、测试、性能记录；本地 release 安装包保留，不作为本次提交内容。
- 现有验证：前端 57 项、界面 32 项通过；类型检查、前端构建、最新原生 cargo check 通过。此前 Rust 29 项测试通过；窗口按需创建后的原生交互仍需实机回归。

## 2. 目标与约束

最终 Windows 程序不创建 WebView2，不依赖 Svelte、DOM、JS 或浏览器渲染进程。保留当前视觉设计、弹簧动画、实时频谱和功能，不通过默认关闭功能达到资源目标。

默认以 Windows 10/11 x64 为迁移范围；最低 Windows 版本在原型阶段结合 API 与实机验证确定。当前不扩展其他操作系统，也不同时更改设置格式、产品功能或发行版本号。

UI 保留：40px 顶部工具栏、28px 点击区、16px 图标、无可见功能名称、同屏最多 5 项；现有功能顺序及时间/天气；空白收起、Escape 返回、长歌名渐变滚动、四边贴靠和悬浮模式。

## 3. 首选技术路线（原型验证后锁定）

- Rust + `windows` crate：复用既有 Rust 业务与 Windows API 经验。
- Win32 HWND：窗口、消息循环、托盘、快捷键、DPI、屏幕工作区与命中测试。
- Direct2D + DirectWrite：岛轮廓、图标、文字、刻度尺、频谱和渐变。
- Direct3D/DXGI + DirectComposition：透明表面与 GPU 合成、变换和透明度动画。
- 自定义页面树：音乐、音量、倒计时、时间、天气；只构建当前页面。
- UI Automation：图标按钮名称、焦点、键盘导航、音量滑块数值、可访问性事件。

这条路线以细致控制异形窗口与生命周期为目的，不保证仅因“原生”就自动低内存。不要同时接入第二套 UI 框架。若原型不能稳定实现透明命中、文字质量或资源目标，先记录失败原因并重新评估框架，再全面迁移。

纯图形合成解决不了所有控件问题：Studio 的文本输入、IME、选择、滚动、搜索、下拉菜单和辅助功能均需要专门实现/封装原生控件。MV 视频应评估 Media Foundation，不能以保留隐藏 WebView 的方式声称已完成原生化。

参考依据：

- [微软 Rust for Windows](https://learn.microsoft.com/en-us/windows/dev-environment/rust/rust-for-windows)：Rust 可调用 Win32、COM、WinRT API。
- [微软 DirectComposition 示例](https://learn.microsoft.com/en-us/windows/win32/directcomp/directcomposition-code-samples)：原生合成与动画示例。
- [微软 DirectComposition 表面](https://learn.microsoft.com/en-us/windows/win32/directcomp/bitmap-surfaces)：绘制表面与桌面合成器的关系。

## 4. 结构和业务拆分

拟新增独立 Cargo workspace（实施时确认目录）：

- `crates/isle-core`：状态、命令、倒计时、设置结构、播放器选择与业务规则，不依赖 Tauri 或窗口类型。
- `crates/isle-platform-windows`：GSMTC、WASAPI、音量设备、托盘、热键、自启动、显示器与截图保护等系统服务。
- `crates/isle-ui`：几何、布局、绘制、动画、交互、可访问性与页面生命周期。
- `crates/isle-app`：原生可执行入口、服务装配、窗口管理与退出清理。

旧 Tauri 外壳暂时保留，通过适配层使用提取后的 core；最终原生可执行文件的依赖树不包含 Tauri/Wry/WebView2。过渡期两个版本分开运行，不同时争用热键、托盘、配置写入或音频采集。

| 当前实现 | 处理方式 |
|---|---|
| `src-tauri/src/services/media.rs` | 保留媒体协议与封面匹配；将 `AppHandle` 设置读取改为显式业务配置 |
| `src-tauri/src/audio.rs` | 保留 WASAPI/FFT；替换 Tauri Emitter，使用有界最新帧通道 |
| `src-tauri/src/services/settings.rs`、`models/settings.rs` | 保留字段及兼容规则；路径解析、文件写入与自启动适配拆开 |
| `src-tauri/src/services/idle.rs` | 保留天气/系统信息；取消 UI 框架耦合，保持城市缓存隔离 |
| `src-tauri/src/event_bus.rs`、`lib.rs` | 改为类型化应用事件和生命周期服务，替代全局 Tauri AppHandle |
| `src/lib/countdown.ts`、`mediaClock.ts` | 移植到 Rust core，沿用时间线、暂停、跳转、截止时间测试用例 |
| `src/lib/islandGeometry.ts`、`islandMotion.ts` | 移植纯几何与运动模型，绘制与鼠标命中共用输出 |
| `IslandSurface.svelte`、各 Panel、Studio、FloatingWindow | 原生重写；保留截图、交互及无障碍语义作为验收基准 |

服务拥有媒体状态和倒计时截止时间；窗口只拥有其显示订阅。页面关闭释放绘制资源、图片纹理、动画、观察任务与独占请求。共享采集/请求使用消费者计数，最后一名消费者退出才停止。GPU 设备丢失后重新创建资源，但不重置业务状态。

## 5. 动画实现原则

- 宽、高、圆角、凹肩统一使用可打断弹簧，保持当前位置和速度；先对齐现有 `stiffness=0.18`、`damping=0.8` 的视觉响应。
- Svelte 参数不是物理单位，不能直接当作另一积分器的系数。通过录制展开、收起、快速反向操作的轨迹校准，明确时间步长和收敛阈值。
- 变换与透明度尽量交由合成层；实际路径形变按需重绘。形状、裁剪和命中测试使用同一帧状态。
- 稳定后停止形变帧；频谱可见播放时保持实时更新。长歌名仅在溢出且可见时滚动，24px/s、两端停留 1.2s。
- 减少动画直接到达目标；多屏移动、贴边锚点和 DPI 变化不能造成闪白、抖动或透明区域拦截鼠标。

## 6. 阶段与交付

时间为单人全职工程估算，阶段包含测试，整体预计 4～8 周；原型结果后调整，不是已经承诺的完成日期。

### P0：可比较的现有版本基线（约 1～2 天）

构建 `e1e050a` release 可执行文件；记录 OS、CPU、GPU、屏幕刷新率、DPI、设置、媒体素材。补齐原生进程与 WebView 子进程的受控占用数据。现有 Chrome 页面数据及任务管理器截图只作辅助，不作为新版原生收益的分母。

交付：可回退构建、统一测量脚本、固定场景与截图/动画参考。

### P1：独立原生渲染原型（约 3～5 天）

创建独立可执行文件，先用固定媒体数据实现：透明异形岛、四边贴靠、点击穿透、缩放、多屏移动、弹簧连续打断、封面、渐变长标题、频谱曲线和顶部图标栏。原型不得启动 WebView2。

验收：视觉与命中正确；减少动画正确；完成同场景资源与帧时间对比。若内存收益不足或 GPU/CPU 明显恶化，先诊断，暂停扩大迁移范围。

### P2：核心逻辑解耦与真实媒体（约 5～8 天）

引入真实 GSMTC/WASAPI、播放器优先级、进度校准、播放控制、网易云封面、音量设备、共享订阅与有界缓存；迁移倒计时业务状态及既有测试。

验收：切歌、暂停、恢复、跳转、设备切换、播放器退出/重启、多窗口消费者变化后状态正确。封面切歌无错配，缺少元数据不会永久卡住。

### P3：完整主岛和辅助播放器（约 5～8 天）

完成音量、倒计时、时间、天气、设备菜单、直接操作、独立倒计时、悬浮播放器、MV/封面效果，以及托盘、热键、自动隐藏与截图保护。

验收：旧版功能清单逐项对照；关闭页面不停止倒计时或音乐；时间跨分钟/时区、天气城市切换/失败缓存、快速切换和多屏均通过。

### P4：原生 Studio 与设置迁移（约 5～10 天）

实现外观、媒体、系统、位置、语言、字体、城市搜索等设置；预览使用同一原生渲染组件。完成键盘、IME、焦点、屏幕阅读器支持。保留现有设置并在首次迁移前备份，避免不兼容的新格式覆盖旧配置。

验收：所有设置可编辑并正确持久化；关闭释放窗口；重新打开恢复设置；主岛与 Studio 预览一致。

### P5：资源、兼容性与发布验证（约 3～7 天）

测试 Windows 10/11、100/125/150/200% DPI、60/120Hz、混合 DPI 多屏、休眠恢复、屏幕拔插、音频切换、显卡资源重建。完成发行构建依赖审计及旧版回退说明。

验收后才将原生版本设为默认。安装包只在明确要求交付安装包时生成；本次只完成保存源码与规划。

## 7. 性能和画质验收协议

以下是待原型验证的工程目标，不是已实现数据：

- 比较同机、同素材、同设置的 release 版本；关闭开发工具和后台构建。场景预热 30 秒，每次采样 60 秒，每场景重复 3 次，报告中位数及范围。
- 场景：空闲收起、音乐播放收起、音乐展开、音量/倒计时详情、天气、全部辅助窗口打开、辅助窗口关闭、主岛隐藏。
- 统计整个应用进程树的 CPU、私有内存、工作集；说明工作集合计可能重复计算共享页。CPU 同时标注单核或全机归一化口径。
- 同时观察 DWM/GPU 开销，防止仅把消耗转移到系统合成器。保留实时频谱及动画，不使用假数据替代最终对比。
- 初步目标：相同功能下常驻私有内存比受控旧版下降至少 30%，争取 50%；原型测量后再确定绝对 MB 预算。
- CPU 不高于基线正常波动范围；静止且无可见实时内容时无持续渲染循环。
- 60Hz 下以稳定 60fps 为目标，记录呈现帧间隔、p95/p99 和超时帧；120Hz 单独验证，不以平均 FPS 掩盖卡顿。
- 100 次页面切换、30 次辅助窗口开关后，窗口数、句柄、订阅数回到基线；预热后的私有内存无持续上升趋势。缓存解释需附上限和清理证据。
- 对照截图和轨迹：透明边缘无黑边，文字清晰，锚点稳定，弹簧可连续打断，无空白闪烁。动画质量与资源目标必须同时通过。

## 8. 第一批实施任务

1. 保存当前 release 测量基线及媒体/显示设置。
2. 创建独立原生 prototype crate，建立 HWND + Direct2D/DirectComposition 最小透明绘制链。
3. 移植几何与命中测试，先验证四边贴靠和不同 DPI。
4. 移植弹簧轨迹，测试快速展开/收起与减少动画。
5. 加入固定封面、字体、频谱、工具栏，完成第一轮资源测量。
6. 形成原型评审记录后进入业务解耦，不提前删除旧 Svelte 代码。
