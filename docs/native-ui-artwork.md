# 原生封面与网易云时长补全

2026-09-27，接续 [真实媒体第一步](native-ui-media-integration.md)。本阶段仍在独立原生工作区实施，没有修改现有 Tauri 产品和已安装版本。

## 已实现

- 优先读取 Windows 媒体会话缩略图，使用原生 BitmapDecoder 解码后交给 Direct2D 绘制；不经过 Base64、HTML 或 WebView。
- 网易云歌名和歌手规范化后须完全匹配，才采用搜索/详情中的时长与专辑封面。无匹配不选相似歌名、翻唱或现场版。缺少歌手时不做网络猜测；这是偏保守的策略，别名、多艺人次序等仍可能需要后续增强。
- 搜索接口无结果时按纯歌名重试，兼容 `artists/album/duration` 与 `ar/al/dt` 字段，歌曲详情失败保留搜索结果时长。时长只补齐未知值，不覆盖播放器提供的有效值。
- 缩略图缺失时只接受网易云图片 CDN，使用 256 尺寸请求；最终中心裁剪成 128×128、预乘 BGRA，并一次性计算抗锯齿圆角。播放器封面先显示，网络补全不阻塞它。
- 网络和解码归单独 WinRT 线程，媒体控制线程继续工作。跨线程缩略图使用 AgileReference；没有自行把 COM 接口标记为线程安全。

## 生命周期与预算

| 项目 | 限制/行为 |
|---|---|
| 排队任务 | 仅一个最新任务；曲目 key 和代数隔离过期结果 |
| 网络开始 | 等待 300ms，快速切页/切歌可直接取消 |
| 请求频率 | 每个媒体服务最多 18 次 HTTP 请求/分钟 |
| 整个任务 | 最多 8 秒；取消状态以 10ms 间隔检查 |
| 下载 | 流式读取，最多 2 MiB，不依赖 Content-Length 可信性 |
| 解码源 | 宽高均不超过 4096，且不超过 16MP |
| 输出图片 | 128×128×4 = 64 KiB |
| 缓存 | 最近 8 首，约 512 KiB 像素；成功完整结果 24 小时，失败或不完整结果 30 秒 |
| GPU 纹理 | 只保留当前音乐页封面，换页/收起/隐藏释放 |
| 关闭/取消 | 主动关闭 HTTP 客户端、响应、流和写入器，退出时等待工作线程释放 |

隐藏和非音乐详情页取消页面专属任务，保留有上限的纯数据缓存。返回同一曲目复用缓存；返回已换歌的播放器重新匹配。缓存不包含页面、窗口、HTTP 客户端或 COM 流对象。

## 验证

- 24 项默认单元测试通过：包括真实 Windows 解码、像素顺序、圆角透明度、损坏图片、取消代数、曲目结果隔离和超过 8 条的缓存上限。
- 可选联网测试通过：在不提供播放器缩略图时，`大鱼 (唱片版) / 周深` 经搜索、详情、CDN 共 3 个请求取得 317597ms 时长及 128×128 封面。测试默认忽略，显式运行才联网。最初选择的测试曲目没有通过严格匹配，换用了接口已确认存在的曲目，未放宽匹配规则。
- 本机真实播放器验证：此前缺失的时长成功补齐到 314133ms，封面在原生窗口中显示；已检查截图中的位置和圆角。测试没有发送播放/切歌指令。
- 功能和隐藏场景脚本：`python scripts/live_media.py --require-artwork`；可见和隐藏各 60 秒，12 次功能页往返，并检查纹理释放、隐藏期间请求数不增长、缓存不超过 8 条。

## 仍未完成

总时长补全不等于实际播放位置补全。如果播放器持续报告位置 0，原生版只能从收到的快照开始本地外推，不能可靠推断程序启动前已播放多久。不能将这一情况宣称为精确进度已经修复。真实频谱、系统音量/设备、天气、Studio、完整多窗口共享资源和全量迁移验收仍待后续实施。

本文的阶段测量不代表完整应用最终占用；尚未添加真实音频采集，也没有与旧版完整程序做等价负载比较。
