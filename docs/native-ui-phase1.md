# 原生 UI 第一阶段执行计划

状态：2026-09-27 已开始实施，独立原型已构建运行，阶段验收尚未全部通过。实际证据见 [首轮记录](native-ui-prototype-results.md)。对应总计划： [native-ui-migration-plan.md](native-ui-migration-plan.md)。

后续进展：已在独立原型中开始接入真实媒体，详见 [媒体接入记录](native-ui-media-integration.md)。这不替代本阶段尚未完成的实机验收，也不代表全量迁移完成。

本阶段交付一个能独立启动、交互和测量的原生灵动岛原型。它验证技术路线，不替代日常使用版本。最终全量迁移仍按总计划 P2～P5 执行。

## 已确定的边界

- 回退源码：`e1e050a`，保留现有 Tauri 构建入口。
- 实施分支：从包含规划文档的准备分支创建 `codex/native-ui-prototype`；其产品代码基线仍是 `e1e050a`。
- 原型使用独立 Cargo workspace、独立可执行文件和临时配置目录，不引用 `isle_lib`，避免间接引入 Tauri/Wry。
- 首版只添加 `crates/isle-ui` 和 `crates/isle-app`。业务接入时再引入 core/platform，避免提前搬动旧程序。
- 原型默认手动启动，不注册自启动，不抢占现有全局热键，不写旧版设置文件。
- 主岛使用 Rust + Win32 + Direct2D/DirectWrite + DirectComposition。库版本在第一项构建任务中检查所需 API 后固定，不跟随 latest 自动升级。
- 页面仅保留当前实例；开关页面不拥有音乐或倒计时生命周期。

## 原型模块接口

以下为设计契约，名称可在实现中调整：

- `IslandState`：模式、当前页、贴边方向、锚点、动画偏好、工具顺序与滚动位置。
- `LayoutSnapshot`：本帧 DIP 尺寸、轮廓路径、控件矩形、裁剪区；渲染和命中共用同一份结果。
- `HitTarget`：透明、岛内空白、按钮、滑块、滚动区域；不以整个矩形窗口作为可交互范围。
- `InputAction`：展开/收起、切换页、返回、激活控件、拖动/滚动。取消或超过拖动阈值的手势不生成 click。
- `SpringState`：当前位置、速度、目标、最后更新时间；统一计算尺寸与轮廓，收敛后精确写入目标值。
- `PageInstance`：持有本页布局、文本和图片资源句柄；析构释放，应用级缓存只保存必要的共享数据。
- `FrameScheduler`：只在形变、可见频谱、长标题滚动或内容变更时请求帧；区分内容更新和显示刷新。
- `RenderDevice`：拥有 GPU 设备与窗口绘制目标；设备丢失时重建图形资源，页面选择和应用状态不重置。

## 第一阶段最重要的三个验证点

### 透明区域的跨进程点击穿透

不能仅测试岛内元素命中。测试岛轮廓外的透明角、凹肩及变形过程中的透明区域，确认能操作下面另一进程的窗口。评估 Win32 命中、区域及样式的实际组合；不能只因返回了 HTTRANSPARENT 就判定所有跨进程场景通过。

### 动画响应与视觉一致

记录旧版 60Hz 下的宽/高/圆角/凹肩轨迹，再校准原生弹簧。现有 stiffness/damping 是 Svelte 的实现参数，不直接当作物理系数使用。测试展开→立即收起→再次展开、详情快速切换、悬浮/贴边变化、减少动画及恢复。

### 内存对比的口径

原型先比较双方相同固定场景的 UI 成本；接入真实媒体、封面、天气和 WASAPI 后，再比较整个应用的成本。记录私有内存、工作集、句柄、线程、窗口、CPU与呈现帧间隔，观察 DWM/GPU，避免遗漏被转移的开销。

## 场景验收清单

- [ ] 悬浮、顶部、底部、左侧、右侧：展开/收起、控制点击和透明处穿透。
- [ ] 100%、125%、150%、200% DPI；混合 DPI 屏幕迁移；显示器工作区约束。
- [ ] 1、5、7 个工具；图标名称通过 tooltip/无障碍提供；横向滚动和键盘选择。
- [ ] 长歌名 24px/s 往返、两端各停 1.2s；短名称静止；减少动画静态渐变。
- [ ] Escape 返回、音乐页 Escape 收起；空白收起；控件、拖动和取消手势不误收起。
- [ ] 收起重开回音乐页；当次展开保留工具栏滚动位置。
- [ ] 100 次切页和 30 次窗口开关后资源数量回落；停用页面无更新任务。
- [ ] 窗口启动、退出、失焦、最小化、屏幕拔插、休眠恢复、设备资源重建。
- [ ] 固定场景预热后测量，每次 60 秒、重复 3 次；动画单独测帧间隔。
- [ ] 原型进程树无 WebView2，运行依赖无需浏览器运行时。

## 第二阶段开始时的拆分顺序

1. 抽取设置结构和纯数据类型，将文件路径通过依赖注入提供。
2. 移植 countdown/mediaClock 及现有测试用例，不随窗口销毁而丢失截止时间。
3. 媒体服务移除 AppHandle 参数，播放器筛选配置显式传入。
4. 将 EventBus 的 Tauri 输出适配为类型化事件；状态事件有序，频谱只保留最新帧。
5. 将 WASAPI 生命周期从窗口移到应用服务，并验证最后一个消费者退出后的停止。
6. 完成真实媒体场景对比，再接入天气/设备控制/悬浮播放器。

一个原生原型 exe（不打安装包）、构建说明、原型截图/动画、资源测量结果和已知差异清单。原型预计 3～5 个工作日的工程量，透明穿透或驱动兼容问题可能延长；完整迁移约 4～8 周，待原型结果重新估算。
