# 原生媒体接入第一步（2026-09-27）

后续状态：封面和网易云时长补全已继续接入，见 [原生封面与时长补全](native-ui-artwork.md)。本页下方保留首次接入时的范围和测量记录。

## 本次范围

在独立原生工作区新增无平台依赖的 `isle-core`，移植旧服务的播放器选择规则及进度处理原则。现有 Tauri 产品代码没有改动，没有引入 `isle_lib`、Wry 或 WebView2。设置存储、封面、频谱等尚未提取为共享服务，此次不能视为 P2 全部完成。

运行 `target/release/isle-native.exe --live-media --page music` 可查看真实媒体。默认演示入口保留，现有几何与交互测试不会操作用户的播放器。

## 数据与线程边界

- 窗口线程仅消费快照、绘制并发送命令；WinRT 管理器和会话全部归独立媒体线程所有。
- 可见音乐页或收起状态每秒刷新状态与进度；歌名/歌手首次读取，之后收到 `MediaPropertiesChanged` 才重新读取，避免逐帧请求元数据。
- 切到音量、倒计时等详情页或隐藏窗口：取消未完成异步读取，解除事件订阅，释放管理器与会话，工作线程阻塞等待激活。恢复重新获取，旧会话编号的命令失效。
- 最新快照只保留一个；更新通知合并，命令队列最多 8 条，超过 2 秒的控制命令丢弃。控制前检查播放器能力和目标会话编号，不乐观修改播放状态。
- 异步 WinRT 操作以 10ms 间隔检查完成/取消，最多等待 2 秒；页面事件和渲染不等待这些操作。同步 COM 属性调用仍依赖系统服务响应，不能宣称所有外部调用都有硬性超时。
- 只有一个原生窗口消费者。接入悬浮播放器等窗口前，需提升为共享服务与消费者计数，避免一个页面释放其他窗口仍在使用的资源。

## 进度与缓存

- 从单调时间投影播放位置，暂停不继续外推，位置不超过已知时长。
- 重复的稀疏快照不重置计时基准，缺失的时长只在同一首歌内继承，切歌清空。位置变化仍尊重播放器报告，可回到零。
- 不用播放器的 `LastUpdatedTime` 二次推算位置；其值只用于自动会话选择排序，沿用旧服务对过期时间戳的处理原则。
- 总时长缺失时显示空进度，未添加假时长。此次实机媒体确实报告总时长 0，网易云补全仍是后续明确任务。
- 当前标题布局最多一个；音乐页不可见时释放。元数据字符串有长度上限，没有歌曲历史或无界图片缓存。
- 真实频谱、封面与网络请求尚未迁移，真实媒体模式的频谱位置是静态占位；此次内存数字不能代表完整应用。

- `cargo fmt`、严格 Clippy、21 项工作区单元测试、release 构建均通过。
- 真实只读会话接入及窗口截图检查；采样不发送实际播放控制命令。
- 可见/隐藏各采样 60 秒，隐藏阶段检查无媒体轮询、无呈现帧、无展开页、无图形渲染器；12 次功能页往返检查释放和重建。
- 播放/暂停、上一首、下一首已连线，但尚未针对受控测试播放器执行端到端验证，不能标记为验收完成。

## 刷新策略

真实模式的进度只有在音乐页可见、正在播放且时长有效时按秒重绘。无时长或暂停状态不启动进度重绘定时器，媒体线程仍按秒读取以检测状态变化。标题溢出且启用动画时沿用原生动画帧；减少动画模式使用静态渐变。未通过默认关闭已实现功能来降低测量占用。

切换功能页保留最近歌曲的单调时钟基准，返回后若还是同一曲目则继续；新曲目重新建立基准。媒体线程的事件订阅和管理器仍会在没有可见消费者时释放。

同一原生进程，预热 5 秒，可见和隐藏各采样 60 秒。启用减少动画，读取实际正在播放的媒体；该播放器报告时长为 0，标题保持不变，封面/频谱尚未接入。基准窗口禁止用户输入，脚本仅在采样后发送页面导航键。首轮收到额外输入的数据已弃用，表格来自最后一轮。

12 次音量页→音乐页往返后，私有内存从 57.96 MiB 到 57.91 MiB，句柄保持 497，没有逐次上升。短期循环通过不等于长期泄漏验证通过。默认演示模式的导航冒烟检查和 UIA/MSAA 控件回归检查也已通过。

这些是部分功能、减少动画和静态内容下的阶段数据，不是完整产品播放频谱/滚动标题的最终占用，也不能与用户任务管理器截图直接计算降幅。完整应用的等价 WebView 基线、正常动画/频谱场景、30 秒预热及三轮重复测试仍待后续实施。
