# 原生时钟时区

2026-09-27，U04/S04 的时区选择、保存与显示接入完成。

## 功能

- 原生设置增加时区下拉框，沿用旧版六项：系统、台北、东京、纽约、伦敦、UTC。与工具/动画设置一起后台保存，成功后立即更新时钟，重启恢复。
- 时钟页显示所选时区的时间、日期及名称。只转换应用内显示，不修改 Windows 时间或系统时区。
- 使用 [SystemTimeToTzSpecificLocalTimeEx](https://learn.microsoft.com/en-us/windows/win32/api/timezoneapi/nf-timezoneapi-systemtimetotzspecificlocaltimeex) 按 Windows 动态夏令时规则转换 UTC。四个固定区域的 Windows 时区标识在启动时枚举缓存，不在每帧重新枚举。
- 保持既有分钟对齐刷新；无新增采集线程、网络请求或持续动画。
- 无法转换时显示 `--:--` 和原因；未知旧时区保留为设置列表的一项，不默默改为系统时区，也不因修改其他开关而覆盖其原值。

## 验证

- 格式、严格 Clippy、Release 构建通过。完整测试 49 项通过，随后新增未知时区保留用例单独通过，共 50 项；既有网易云联网用例默认忽略。
- 固定 UTC 输入验证纽约春季跳过一小时、秋季重复一小时，伦敦春季转换，以及台北跨年、东京跨日、UTC 不偏移。
- 左侧副屏实测六个选项轮流应用，保存后时区即时更新；重启恢复 UTC；工具关闭/恢复、F8、草稿取消仍通过。
- 五组启动保护场景通过，包括未知旧时区：显示“不支持”，原文件保持不变，无天气请求。
- 已检查 UTC 时钟与设置窗口截图，日期、时区文字和控件没有裁切。截图仅保留本地。

证据：[设置及六时区切换](performance/native-clock/native-settings-results.json)、[启动保护](performance/native-clock/configuration-fault-results.json)。所有 UI 测试均在左侧 DISPLAY2，以不抢焦点方式运行。

## 边界

支持范围与旧版设置选择项一致，并非完整 IANA 时区浏览器；任意旧字符串不会自动转换为近似时区。夏令时数据依赖本机 Windows 时区数据库。本阶段未修改系统时间进行测试，时钟跳变/睡眠恢复的长期实机矩阵仍待后续验收。Studio 外观、实时预览、其他系统设置与辅助窗口继续迁移。
