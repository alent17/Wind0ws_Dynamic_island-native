# 原生实时频谱迁移

日期：2026-09-27。独立原型阶段，日常安装版未替换。

## 已接入

- 原生 WASAPI 共享模式输出回环，不经过 Tauri、JavaScript、WebView2 或 Base64。只打开 `eRender/eMultimedia` 默认输出，不打开麦克风。
- `--live-media` 同时启用真实媒体、封面、频谱和系统音量；`--live-spectrum` 单独检查系统输出频谱，此模式的歌名和播放按钮仍为演示数据。
- 六根频谱条仍在音乐信息右侧，收起岛也使用同一份最新频谱。只挂载当前页面，没有另外创建频谱窗口。
- FFT 使用 RustFFT 6.4.1、2048 个采样点和 Hann 窗，沿用旧版的六段频率与增益：20–250、250–600、600–2000、2000–5000、5000–10000、10000–20000Hz。
- 支持 32 位浮点以及 16/24/32 位整数 PCM，包括对应的 WAVEFORMATEXTENSIBLE；验证声道数、采样率、块对齐和格式。其他格式报错并退避重试，不按错误类型解释字节。

## 调度与释放

| 层级 | 行为 |
|---|---|
| 采集 | 独立 COM 线程，音频事件唤醒；控制事件负责停止/重建/退出 |
| 分析 | 最多约 20 次/秒，固定环形缓冲，仅分析最近 2048 点；FFT 临时空间预分配 |
| 传递 | 只保留最新 6 个幅值；窗口消息合并，代数隔离已经失效的采集结果 |
| 平滑 | 按时间计算快起慢落；界面沿用约 60Hz 单次帧计时器，采集更新不额外插入绘制帧 |
| 静止 | 幅值量化过滤亚像素噪声，收敛后不请求连续帧；无音频包超过 200ms 清空旧结果 |
| 减少动画 | 直接显示分析结果，取消插值；继续提供真实频谱数据 |
| 非音乐页/隐藏 | 停止客户端，释放采集接口、端点、事件、FFT 与样本缓冲；等待下一次可见需求 |
| 暂停 | 真实媒体模式跟随媒体播放状态停止采集；独立频谱测试模式不依赖演示播放状态 |
| 设备变化 | 约每秒按默认设备 ID 检查；变化时释放旧流并重建，清空旧波形 |
| 错误 | 清空频谱、记录诊断错误、约一秒后重试；等待期间可以立即停止或退出 |

采样数据只存在工作线程固定内存中，不写文件、不上传、不传到 UI。线程退出前释放 COM 对象，主窗口销毁前等待线程结束。当前仅一个原生窗口，未来多窗口的共享消费者计数仍需实现。

## 验证

- 格式检查、严格 Clippy、release 构建和 31 项默认单元测试通过；1 项可选联网封面测试本轮未执行。
- 新增真实 PCM/浮点字节解码、非法格式拒绝、44.1/48/96kHz 六频段正弦响应、静音/非有限输入/清空，以及 UI 收敛和非音乐页不请求频谱帧测试。
- `scripts/live_spectrum.py` 使用本机已有声音，验证真实非零频谱、切页和隐藏释放、恢复采集、12 次切页以及快速隐藏/恢复。测试不播放声音、不控制播放器、不改音量。
- `--quick` 使用每场景 5 秒，正式测试使用 60 秒。静态基线和频谱场景使用同一 release 构建、同一个音乐页和默认动画设置，基线关闭模拟播放；频谱场景添加 `--live-spectrum`。
- `scripts/live_media.py --quick` 验证真实媒体、封面与频谱联合运行：获得有效时长、64KiB 封面和非零频谱，隐藏后媒体轮询及频谱包/分析计数停止，12 次切页正常重建。这个 5 秒快速样本用于功能回归，不作为正式性能表的数据。
- 默认演示模式导航及 UIA/MSAA 回归通过；加入频谱后没有改变控制按钮的无障碍树。
- 已检查本机截图，六根条的横向位置未改变，长标题与频谱仍使用原有布局边界。截图含桌面内容，只保留本机，不提交仓库。

## 限制与后续

- 采集的是默认设备上的系统混音，可能包含其他应用声音，尚不是所选播放器的单进程音频。声道平均沿用旧版，反相声道可能相消。
- 支持事件回环的目标为 Windows 10 1703 及以上。默认设备迁移代码已实现，真实拔插、蓝牙模式切换、驱动失效和睡眠恢复仍待实机验收。
- 频谱启动受真实媒体播放状态影响，媒体服务每秒读取，因此开始/暂停可能有约一秒延迟。
- 循环测试属于短期资源检查，不代表完整应用长期无泄漏。天气、Studio、多窗口、设置迁移和全量等价负载对比仍未完成。

API 依据：[WASAPI 共享回环与事件支持](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)、[采集包、静音标志和 ReleaseBuffer 配对](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer)。

## 资源测量口径

三个场景均每秒读取一次相同的诊断快照，避免不同采样开销影响差异；每个可见场景预热 5 秒，随后采样 60 秒。CPU 按全部逻辑处理器归一化，包含测试诊断写盘成本。声音来自用户当时已有播放，未使用受控音频，因此表格描述本机这轮观察，不代表固定声音负载下的精确增量。

静态基线与实时频谱均为原生程序；这不是完整 WebView2 版本的对照，不能据此宣称全量迁移已经达到最终降耗目标。`presentCallIntervalP95Ms` 是相邻 Present 返回间隔，不是 DWM 上屏延迟。

12 次切页的首尾私有内存为 59.30→59.41 MiB，句柄均为 509；没有观察到持续逐次增长。之后的 10 次快速隐藏/恢复也成功停止最终采集，旧波形归零。运行期间没有子进程。
