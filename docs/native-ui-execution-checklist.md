## A. 已确认的第一阶段

已确认开始第一阶段 N00～N08：先做可独立运行的原生原型，再根据测量结果评估全面迁移。完整迁移仍需逐阶段验收。

若决定实施，默认按以下范围推进：Windows 10/11 x64、现有视觉和功能、保留 Rust 业务、最终去掉全部 WebView2。原型使用独立分支、独立配置和可执行文件。产品代码回退点为 `e1e050a`。

后续阶段每阶段均有验收关口。任何无法达到的效果要列入差异清单，不能以“迁移完成”掩盖缺失功能。

## B. 最终交付边界

- 主灵动岛、Studio、悬浮播放器、独立倒计时全部原生。
- UI、天气、频谱、MV、设置或隐藏页面均不借助 WebView2。
- 保留播放信息、进度/跳转、封面补全、播放器筛选/排序及启动播放器。
- 保留实时/随机频谱、暂停行为、设备切换、音量调节与静音显示。
- 保留倒计时、完成提示、时区、日期、天气与三天预报、无播放器状态。
- 保留悬浮播放器缩放/锁定/置顶/位置、圆形封面、像素化、网点、MV及封面主色。
- 保留托盘、自启动、屏幕选择、贴边方向、透明命中、全屏/截图/录屏/共享屏幕相关设置。
- 保留语言、字体、动画/减少动画、颜色、不透明度、凹肩/圆角、工具开关和 Studio 实时预览。
- 历史设置字段即使当前 UI 没有入口，也在读取/写回时保留，不静默丢失。

## C. 阶段二：业务解耦与真实媒体（P2）

| ID | 任务 | 验收证据 |
|---|---|---|
| C01 | 提取配置、媒体、音频设备、天气、计时数据模型；引入与 UI 无关的 AppContext | core 编译不引用 Tauri/窗口；旧配置测试通过 |
| C02 | 分离路径解析、存储和自启动适配；显式传入播放器选择/排序配置 | 两套外壳可使用同一模型，不交叉覆盖配置 |
| C03 | 移植 countdown 与 mediaClock | 原用例覆盖倒计时截止、暂停/恢复、完成一次、暂停跳转、切歌重置和缺失时长 |
| C04 | 媒体会话采集和控制迁移 | 网易云/Spotify/QQ音乐/浏览器等实际可用会话逐项验证；不能验证者注明环境缺失 |
| C05 | 音频采集、FFT与设备控制迁移 | 保持当前频谱参数；设备拔插恢复；暂停/无消费者时停止；不重复捕获 |
| C06 | 封面请求/解码/缓存迁移 | 同轨请求合并；切歌丢弃旧结果；缓存有界；无重复 Base64 传输 |
| C07 | 统一应用事件和服务关闭 | 状态顺序正确、无阻塞 UI、退出后无线程/任务遗留 |

设计决定：状态控制事件使用有界队列并保持顺序；频谱采用“只保留最新帧”的缓冲区，不允许处理延迟变成无界积压。媒体/封面结果携带轨道键和修订号；天气结果携带城市键；页面独占任务携带取消令牌。UI 不持有后台服务锁执行绘制。

COM/WinRT 初始化与释放归属于明确线程；HWND和需要线程亲和性的图形对象由 UI/渲染线程管理。网络与阻塞系统查询走后台任务，通过消息返回结果。

## E. 阶段四：Studio、配置与可访问性（P4）

- S01：复刻设置分组、预览区和窗口布局，预览复用 isle-ui 同一渲染实现。
- S02：外观参数编辑、拖动预览、应用/撤销逻辑；保留未提交草稿的现有交互语义。
- S03：播放器发现、排序、勾选、刷新及空状态。
- S04：时区/语言/字体、城市搜索、网络失败与请求取消。
- S05：悬浮播放器、图像/MV效果、位置锁定和置顶。
- S06：自启动、显示器、截图/录屏/全屏保护与其他系统设置。
- S07：文本框的 IME、选区、剪贴板、Tab 顺序、下拉列表、滚动、焦点可见性。
- S08：UI Automation 提供按钮名称、滑块范围/数值、状态和焦点事件；图标不会因无文字而不可访问。
- S09：配置导入/保存、原子替换、异常退出恢复、旧字段回写和迁移备份。

设置迁移流程：首次读取旧版文件→验证/补默认值→备份原文件→写入独立原生配置→按字段核对。确认全面切换前不更新旧版自启动路径。兼容序列化字段名、别名和默认值，以现有 AppPreferences 为准。

字体使用现有资源并核对分发许可；图标采用当前图标的等价矢量路径并保留许可。透明表面上的文字采用适合 alpha 合成的抗锯齿，逐项检查中英文、日文、表情和长设备名，不只比较截图位置。

## F. 阶段五：性能、稳定性和发行（P5）

### 实机矩阵

- Windows 10 与 Windows 11；x64 release；记录具体版本、GPU/驱动。
- 100/125/150/200% DPI；单屏、多屏、混合 DPI、主屏更换、拔插和工作区变化。
- 60Hz 与高刷新率；普通 GPU 路径和设备重建。软件回退如可用，单独报告性能，不混入正常 GPU 结果。
- 睡眠/唤醒、锁屏/解锁、音频设备断开、播放器关闭重开、断网/重连。
- 清洁启动、缺省设置、旧配置、有损坏配置、无天气城市、无媒体播放器。

### 占用与生命周期

测量办法和指标采用总计划第 7 节。完整应用相对最新版受控 WebView 基线，以私有内存下降至少 30%、争取 50% 为初步工程目标，原型后校准。CPU、GPU、流畅度必须同时评估。

场景预热 30 秒，采样 60 秒，重复 3 次。页面切换 100 次、辅助窗口开关 30 次，并增加 30 分钟播放/切歌观察。记录句柄数、线程数、窗口数、任务数、缓存大小与呈现帧间隔；出现增长要能定位到具体资源。

缓存初始设计预算（待实测调整）：元数据/解析结果最多 64 条；解码后封面 CPU 内存目标上限 32MiB、GPU 纹理目标上限 32MiB，按实际尺寸计费，主动降采样并采用 LRU；天气保留当前城市及少量最近城市（最多 4 个）；歌词/MV等新增缓存不得无上限。单个过大图像也需尺寸/解码预算保护。

### 最终发行门槛

- 依赖树和运行进程树均确认没有 WebView2/Wry；未启动隐藏浏览器。
- 功能对照表全部完成或逐条获得用户接受的例外。
- 视觉轨迹、透明命中、多屏、输入与可访问性通过。
- 性能结果、已知限制、构建步骤和配置回退说明齐备。
- 用户决定发行后才生成安装包、改默认入口或替换自启动；源码构建不自动等同于发布。

## G. 关键风险与处理

| 风险 | 处理与阶段关口 |
|---|---|
| 跨进程透明点击穿透不成立 | N03 实机先验证；未通过不扩展页面 |
| 弹簧参数移植后手感变化 | N04 对齐轨迹、速度连续性和收敛，不机械照抄系数 |
| 原生绘制转移开销到 DWM/GPU | N07/P5 同时观察系统合成器与 GPU；不能只看应用进程 |
| 自定义控件增加输入/无障碍工作量 | P4 明确 IME、焦点、UIA 的独立任务和测试 |
| 现有服务依赖 Tauri 全局状态 | P2 逐服务拆适配器，先保留可回退旧外壳 |
| 视频解码或媒体源不兼容 | U06 原生验证；未解决不得以隐藏 WebView 兜底后宣称完成 |
| 窗口/纹理/COM对象泄漏 | RAII、明确线程所有权、循环资源计数和设备重建测试 |
| 新旧程序同时使用配置和系统资源 | 独立配置/实例标识，测试期间分开运行 |
| 原型效果好但完整应用占用高 | P2 接入真实采集后重测，P5 才验收最终内存收益 |
