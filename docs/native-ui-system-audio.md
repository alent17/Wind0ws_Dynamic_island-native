# 原生系统音量与输出设备迁移

日期：2026-09-27。独立原型的阶段记录，尚未替换日常版本。

## 接入范围

- `--live-audio` 读取并控制 Windows 当前多媒体默认输出；`--live-media` 同时启用音量服务。默认演示模式保持隔离。
- 原生刻度尺拖动、点击及键盘调节系统音量；点击音量数值切换静音。非零音量调节解除静音，沿用旧版行为。
- 点击设备名进入原生列表，每页最多 4 个输出设备，支持翻页按钮、左右方向键、滚轮和 Tab 导航。Escape 依次返回音量、音乐、收起。
- 当前设备使用蓝色标记。长设备名裁切在固定区域，完整名称通过无障碍接口提供；无设备或读取失败时禁用音量控制并显示提示。
- 列表中的无障碍控件按设备 ID 区分，热插拔、重排、翻页后旧引用失效，避免旧行索引指向另一台设备。

## 线程、任务与释放

Windows Core Audio 的端点和枚举器只在独立 COM 线程创建和使用。音量页可见时每秒采集一次；快照不变时不发界面事件、不重复绘制。界面切到其他页、收起或隐藏后清空待执行命令、释放端点与枚举器，线程阻塞等待再次使用。

音量拖动合并连续命令，命令队列最多 8 条，工作循环至少间隔 20ms。执行前重新核对默认设备 ID 和命令年龄，超过 2 秒的命令丢弃。发现默认设备变化时取消旧拖动。系统回读更新不会再次写回音量。

关闭窗口时唤醒并退出工作线程，等待 COM 引用释放。初始化失败反馈错误状态。仅保留设备和音量的纯数据快照；没有隐藏的页面实例或音频端点对象。当前仅一个原生窗口，多窗口共享服务仍需后续实现。

## 验证与限制

- 严格 Clippy、格式检查、release 构建及 26 项默认单元测试通过；1 项可选联网封面测试本轮未运行。
- 新增队列合并/上限/命令顺序测试，以及 9 台虚拟设备按 4、4、1 分页、逐级返回、收起释放测试。
- `scripts/live_audio.py` 读取本机真实设备，验证设备菜单、返回、隐藏和 12 次切页。整个测试要求 `audioWrites == 0`，报告不保存设备名称或标识。
- 截图保存在本机 `artifacts/audio-volume.png` 和 `audio-devices.png`；已检查实际音量、设备行和裁切位置。
- `scripts/audio_layouts.py` 在悬浮、顶部、右侧、底部、左侧打开真实设备菜单并点击底部空白收起，5 种布局通过且写入数为零，截图已逐项检查。此检查使用原生窗口消息，不等价于鼠标硬件输入全链路验收。
- 默认演示模式的导航冒烟和 UIA/MSAA 回归通过，包括角色、焦点、音量值、旧控件失效和收起移除控件。
- 自动化验证未实际更改用户音量、静音状态或默认设备，因此实际写入效果、拔插和驱动失败恢复仍待实机验收，不能把只读测试当作这些操作已验证。
- 默认输出切换复用旧服务的非公开 `IPolicyConfig` 接口，依次设置 Console、Multimedia、Communications 三种角色；不同 Windows 版本可能不兼容，中途失败可能只切换部分角色，当前提示失败并重新读取多媒体默认设备，不做自动回滚。
- 外部音量/设备变化通过约 1 秒轮询发现；拖动期间仍有设备枚举成本。后续可依据实际拖动采样决定是否引入通知接口，不能用静止页数据证明拖动性能。

## 阶段资源测量

最终构建预热 5 秒，可见音量页和隐藏各采样 60 秒，再往返切页 12 次。减少动画开启，模拟播放关闭，只连接系统音量，不采集频谱或媒体。CPU 按全部逻辑处理器归一化；私有内存与工作集分别记录。
